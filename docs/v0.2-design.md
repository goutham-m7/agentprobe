# v0.2 evaluation evidence design

## Problem and constraints

Users need reproducible repeated trials, uncertainty estimates, annotator input and CI artifacts. Keep the existing async runner, strict Pydantic artifacts and mock demo. Use only independently written code and existing dependencies. No remote writes, paid calls, publishing, arbitrary tool execution or credentials in artifacts.

## Chosen interfaces and data flow

- Extend OpenAIProvider with opt-in bounded retries and caller-supplied per-million token prices. Generation/judging CLI uses two retries by default; target agent transport uses zero because requests may have effects. Retry only 429, 500/502/503/504 and connection establishment errors. Honor bounded numeric Retry-After, otherwise exponential delay. Timeouts/read failures are not replayed. Persist aggregate accounting in a separate usage.json, including missing usage counts: unknown cost is null, not free.
- Scenario branches match a case-insensitive literal substring of the latest assistant text. First matching branch wins; after_turn and next_turn are one-based indices, with next_turn strictly forward. This acyclic representation reuses fixed turns, is bounded by ten prompts and adds no regex/LLM router. Full suite equality remains required by paired comparisons. Branch-dependent paths are related, not identical conversations; reports must say so.
- label consumes a complete Run and produces the existing LabelSet. Prompt all five criteria without showing judge scores. An explicit labeler is required. Write only after every annotation validates; exclusive creation prevents overwrite. EOF/cancel does not create partial evidence.
- Calibration resamples transcript indices, preserving within-transcript dependence across rubric items in the pooled metric. Kappa is undefined when expected agreement is one. Bootstrap intervals use only defined replicates and disclose the number excluded. Degenerate original kappa or no defined replicates yields no interval. Seed/sample count persist in calibration output.
- JUnit uses standard-library ElementTree. Each conversation is one testcase; rubric failures are failures, exceptions are errors. Sanitize XML 1.0 controls. Keep evidence text and let ElementTree escape markup.
- repeat runs the same suite sequentially with bounded concurrency within each run. Persist each run before analysis. Analysis rejects suite/spec/judge/target mismatch; reports sample variance of binary all-criteria success, per-item variance, error count and observed flips. Execution errors are separately counted and make the CLI exit 2, never counted as a successful observation.

## Alternatives and tradeoffs

A separate provider SDK adds dependency weight without a new wire capability. Arbitrary graph plans require cycle budgets and more schema; forward literal branches cover refusal follow-ups deterministically. Normal/asymptotic kappa intervals are fragile on these small binary samples; paired transcript bootstrap is transparent but may exclude degenerate replicates and is not a guarantee of coverage. An internal fake tool executor is deferred rather than claiming arbitrary Python functions are sandboxed.

## Failure behavior and security

Keep response bodies, authorization headers and keys out of exceptions/accounting. Explicit price rates are estimates, not vendor billing; failed requests may still incur unknown charges. No transparent target retries. Label files and transcripts may contain sensitive content and are user-controlled local artifacts. XML is static output, never parsed from a network source. Python target callables remain trusted code, not a sandbox. Repetition multiplies target calls and charges; the CLI exposes the repeat count.

## Rollout and migration

Add optional/defaulted artifact fields for existing suites/runs. No destructive migration. Existing v1 artifacts remain readable. Package stays Python >=3.12, uv_build backend, no new runtime dependencies. v0.2.0 is local only and untagged.

## Acceptance Criteria & Evidence Contract

Each numbered ROADMAP item is a binding acceptance row: provider HTTP tests; branching runner tests; interactive CLI subprocess tests; calibration estimator/CLI tests; parsed JUnit artifact tests; repeat runner/CLI tests; clean-clone and installed-wheel demo evidence. All are integration-level CLI/HTTP/artifact tests except pure statistical validation (unit). Evidence is recorded in evidence.md with exact commands and observed results.

## Verification plan

Test new behavior before implementation. Use transport fakes only at HTTP boundaries and deterministic local agents for runner behavior. Run pytest, Ruff lint/format, offline demo, local build, then fresh local clone install/full checks/demo. Verify a wheel installed outside the source tree. Do not claim paid-model quality or real-human calibration; automated label inputs are synthetic test annotations.
